# Database deployment
EF Core migration 20261117000100_Initial is the deployment authority. It embeds scripts 002–006 as resources in lexical order. Script 001 is cluster setup only, mirrored by Docker init-roles.sh. Never run standalone schema scripts on an EF-migrated database.
Initial migration uses explicit SQL for partitioning, functions and RLS; the DbContext is intentionally SQL-oriented with no tracked domain entities. Future schema changes require new explicit migrations and versioned scripts. Do not edit a migration after deployment.
The API has two isolated credentials: pulse_auth can access local identity and tenant administration tables and a narrow credential lookup function; pulse_app is NOBYPASSRLS and all tenant transactions set pulse.tenant_id transaction-locally. Tenant context never comes from ingestion payloads. App role receives no direct identity-table access. Credential lookup is SECURITY DEFINER with a fixed search path, no public execute and no broad auth access to telemetry.
Maintenance and migrations use separate privileged connections and are never used by request handlers.
Raw telemetry partitions span months, maintained from the previous month through two future months. Retention drops full partitions older than 90 days (effective retention 90 days plus up to a month); ledger retention is 90 days. Rollups recompute the last 96 hours idempotently. Processed outbox is retained 7 days. Back up volumes before destructive maintenance.
ERD: [erd.md](erd.md). Verification scripts are under database/verification; integration tests use an isolated Testcontainers PostgreSQL instance.
