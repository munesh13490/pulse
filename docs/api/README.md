# Local API
Base URL: http://localhost:5080. Login with POST /v1/auth/login and JSON {username,password}. Send the returned accessToken as Authorization: Bearer. Refresh via POST /v1/auth/refresh {refreshToken}; tokens rotate once. Logout revokes the refresh secret. Disabled users are rejected on every management request. Passwords use the ASP.NET Core Identity PasswordHasher format; refresh secrets are SHA-256 hashed.
Roles: platform-admin provisions tenants and users; tenant-admin manages its users, quotas, devices, keys and rules; operator manages devices, keys, rules and alert transitions; viewer reads tenant resources.
Platform administrators have no implicit tenant scope. Create a tenant-admin and log in as that user for tenant operations.
Device ingestion: POST /v1/telemetry with X-Device-Key: identifier.secret and {items:[{eventId,occurredAt,metric,value}]}. Batch size 1–500. Never send tenant identifiers. UTC event times must be within the preceding 72 hours. Responses list accepted, duplicate or rejected items. Unique ledger constraints handle concurrent duplicates; telemetry, ledger and outbox share one transaction.
API keys: POST /v1/devices/{id}/keys {expiresAt}; rotation revokes the previous key under a device row lock. Secrets appear only in that response and are never retrievable.
Alert pages use before/beforeId keyset parameters and optional state. POST /v1/alerts/{id}/transitions {state} validates transitions atomically. /v1/alerts/stream uses authenticated fetch SSE; Redis wakes every replica and durable database snapshots recover missed Pub/Sub. Snapshots contain the latest 100 alerts; older alerts remain available through keyset pagination. Clients replace snapshot records by ID.
Rule threshold compares window average; rate-of-change compares (last minus first value) divided by elapsed seconds in the event-time window (ties ordered by event_id). Rates require two distinct event times. Immutable versions take effect at creation time. Rules are finalized after the 72-hour late-arrival watermark, ordered by event time/event ID; suppression uses event time, not processing time. Ingestion and finalization share a tenant advisory lock to close boundary races. The explicit delay makes outcomes reproducible across arrival orders. Ingestion is immediate, finalized alerts are delayed.
OpenAPI: GET /openapi/v1.json with an administrator token.
